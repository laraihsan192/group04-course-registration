# v0.1.0 — Demo sign-in and course search

Implement FR-01 and FR-02 on the `feature/sign-in-course-search` branch.
Read `docs/requirements.md`, `docs/architecture.md`, and `uml/data_model.md`
before editing. Follow the sign-in and search flows in the architecture.

- FR-01: Let a student sign in with a fictional demo account. Valid sign-in
  opens the course catalog. Invalid sign-in shows a clear error and allows
  another attempt. Require sign-in to access the catalog.
- FR-02: Let the student search by course name or code. Show matching
  courses and their sections, meeting times, and available seats. Show a
  clear message when there are no matches. Use fictional course records
  and sample enrollment counts for this increment.

Keep the scope to sign-in and course search. Registration, dropping
sections, and the semester timetable are later increments.

Add and run automated tests for valid and invalid sign-in, catalog access
before sign-in, search by name and code, section details, and no results.

command and its results, and any design decisions that need team review.
